# SSO++

Фоновый агент единого входа для macOS: ключик 🔑 в строке меню горит значит включен (вход в домен
выполнен), серый — нет. 

Возможности приложения: атрибуты пользователя по LDAPS,
синхронизация пароля домена и пароля Mac, смена пароля из приложения.

Написан c 0 на swift, независим от библиотек

---

# Что она делает

- Пускает в корпоративные ресурсы без пароля.
- Делает пароль Mac и доменный пароль одним паролем. Если они разошлись, программа
предлагает синхронизацию: пароль Mac становится равным доменному. Процедура разовая.
- Меняет пароль сразу в домене и на Mac. Одной операцией, без веб-страницы. Под полем
нового пароля живой чек-лист требований: выполненные пункты зеленеют по мере набора.
- Чистит старые сохранённые пароли при смене. Перед сменой пароля программа спрашивает
подтверждение и удаляет пароли, сохранённые на этом Mac. Иначе macOS продолжала бы молча
предъявлять старый пароль сетевым папкам и почте, домен считал бы каждую такую попытку
неудачной — и учётная запись блокировалась бы сама собой через несколько минут после
смены. Пароли сетей Wi-Fi при этом сохраняются.
- Показывает инфо о пользователе и срок истечения пароля.
- Легкая настройка и деплой как админ.
- **Принимает ввод только латиницей.** Поля логина и пароля переключают раскладку на
английскую при фокусе и не принимают кириллицу.
- Работает без связки с доменом ( ПК не нужно быть в AD), но нужна сетевая связность.
- **LDAP-порт не нужен**

## Требования для работы

- macOS 13 или новее
- домен с Kerberos (отлично работает на AD)
- сетевая доступность контроллеров домена:
- Порты:
  | **88**  | вход, получение тикета
  | **464** | смена доменного пароля (kpasswd)
  | **636** | ФИО и срок действия пароля (LDAPS)

- корневой сертификат организации на Mac — для LDAPS с закреплением

# Администраторам
## Что понадобится

- Mac с macOS 13+ и Command Line Tools: `xcode-select --install` (полный Xcode не нужен)
- домен с Kerberos, открытые с Mac порты 88, 464 и 636


## Первоначальная настройка

Установите и откройте приложение из Finder SSO++,нажимаем настроить и вводим то что требуется, т.к это первоначальная настройка с дальнейшим деплоем конфигурации на тачки, то настроим конфигурацию, экспортируем .plist в файл и деплоим как профиль конфигурации.

### Запасной путь: файлом

Если MDM умеет только класть файлы:
Создаем папку и ложим файл по данным директориям, ставим правила на чтение/запись.

sudo mkdir -p "/Library/Application Support/SSO++"
sudo cp config.plist "/Library/Application Support/SSO++/config.plist"
sudo chmod 644 "/Library/Application Support/SSO++/config.plist"

Приложение прочитает файл при следующем запуске. Профиль, если он есть, всё равно главнее.
